# UI and accessibility

Light theme, Fluent UI controls, blue primary actions and a restrained neutral palette keep operational state readable. Green/amber/red statuses also have text labels. Navigation follows the role's tasks: dispatch, assigned work, supervisor attention, analytics and investigation. Optional technical metadata stays in disclosure panels. Data, empty, pending, error and offline states must stay explicit rather than being replaced with fake records.

Web uses semantic landmarks, associated form labels, visible focus, accessible dialogs, keyboard controls and feedback messages. Replay is read-only and playback only moves the historical cursor. Mobile stage controls have large touch targets; each form preserves drafts and provides assistance when predefined answers do not fit.

Automated browser coverage checks selected desktop and phone layouts. These checks do not establish full WCAG 2.2 AA compliance. Keyboard-only traversal, real screen-reader/VoiceOver/TalkBack use, high zoom, reduced motion and native device contrast should remain part of release acceptance. The mobile device audit is pending.
