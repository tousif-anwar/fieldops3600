# Verify APIs and persisted data locally

Start with the web application at http://localhost:8088 and the installed Android development app. Use the local accounts in the ignored `.local/LOCAL_ACCESS.md` sheet. The application's authorization code flow uses the actual Keycloak login form; the verification scripts use code plus PKCE without saving tokens.

## Repeatable verification

Run from the repository root with the local Compose stack running:

```powershell
python tests/integration/test_live_api.py
python tests/backend/verify_resource_authorization_http.py
python tests/backend/verify_optimizer_http.py
python scripts/verify-database-permissions.py
python scripts/inspect-demo-databases.py
docker compose run --rm --no-deps -v "${PWD}/analytics/quality-tests:/checks:ro" analytics-worker python /checks/run_checks.py
python scripts/verify-observability.py
```

The integration test creates labeled synthetic orders and executes booking, assignment, all eight service stages, concurrency rejection, replay and analytical reads. The authorization and optimizer scripts exercise their named boundaries. A test's successful exit establishes its assertions; it does not certify every endpoint permutation. Read each script and its terminal results when explaining coverage.

The [compiled endpoint inventory](../api/ENDPOINTS.md) lists all eight business services' actual routes and inherited policies. It includes private health/metrics endpoints and SignalR transport routes. The [API reference](../api/REFERENCE.md) describes bodies, roles, gateway routes and errors. Regenerate the inventory after rebuilding changed service images:

```powershell
python scripts/export-api-catalog.py
```

An inventory is separate from executed tests. For an interactive example, open the browser's Network panel, create a work order against a registered customer/location/equipment, and inspect the request body, status, returned ID and correlation header. Book it, continue the native workflow, and show the resulting read responses. Expected 400 validation, 403 role denial, 404 hidden resources and 409 stale-version conflicts are deliberate behavior.

## Show the database behind the screen

`inspect-demo-databases.py` runs `BEGIN READ ONLY` transactions and writes only table names, row counts and unvalidated-constraint names to ignored `artifacts/data/database-counts.json`. It covers all nine FieldOps databases and 71 physical tables. Counts reflect the moment of the observation and grow as tests create records. Migration/transport/idempotency tables can correctly be empty. Their rows are generated by the real runtime, rather than artificial inserts.

To inspect a work order and its outgoing event without displaying contact details, open an interactive database session:

```powershell
docker compose exec postgres psql -X -U postgres -d fieldops_work_orders
```

Then run these read-only statements, replacing the UUID with the order returned by your API call:

```sql
BEGIN READ ONLY;
SELECT "Id", "Number", "Status", "CustomerId", "ServiceLocationId", "AssetId",
       "TechnicianId", "Version"
FROM work_orders WHERE "Id" = 'paste-the-order-uuid-here';

SELECT "Id", "Body"->>'eventType' AS event_type,
       "CreatedAtUtc", "PublishedAtUtc", "Attempts"
FROM outbox_messages
WHERE "Body"->>'workOrderId' = 'paste-the-order-uuid-here'
ORDER BY "CreatedAtUtc";
ROLLBACK;
\q
```

The operational outbox JSON uses camelCase keys, while operational table columns preserve their quoted names. An outgoing publication timestamp means the publisher confirmed delivery to the broker; inspect downstream reporting/warehouse records separately. The [data dictionary](../data/DATA_DICTIONARY.md), [ownership model](../data/OPERATIONAL_DATABASES.md) and [physical diagrams](../data/ENTITY_RELATIONSHIP_DIAGRAMS.md) show actual tables and within-database constraints. Cross-service identities are validated through owning APIs rather than cross-database foreign keys.

## Connect the observations

Use the same order UUID in the web details, native job, API response, operational database and Replay. Then show the broker's consumers/rates and the dashboard requests. Follow the [monitoring guide](MONITORING.md) for Prometheus, Grafana, RabbitMQ and Jaeger. A zero broker backlog is normal when consumers keep up; it is not a failed event flow.

The repeatable local seed is `python scripts/seed-demo-data.py --customers 24 --orders 30`. It preserves existing data and resumes its private manifest. The batch contains fictional contacts/locations, equipment, completed and active workflows, bookings, availability and notification activity created through authenticated APIs. System evidence is produced by those operations. It does not populate absent inventory, billing, maintenance or IoT modules; remaining implementation is recorded in the [feature matrix](../engineering/FULL_STACK_FEATURE_COMPLETION_MATRIX.md).
